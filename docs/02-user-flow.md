# 02 · 用户流程（User Flow）

> 描述 idea-launch 完整用户流程。V1 Complete：已实现「首页 → 输入想法 → 检查配置 → 首次理解 → 信息补全 → 产品分析 → MVP 范围收敛 → 执行方案 → 最终一致性审查（Final Review）」全链路。

## 总览

```
首页
 → 输入产品想法
 → 检查模型配置
 → 首次理解（Idea Understanding）
 → 判断信息是否充分（Clarification Question Generation）
 → ├─ 需要补充：逐题回答（Clarification）
 │  └─ Clarification Synthesis → Clarified Context
 └─ 无需补充（0 题）：自动 Clarification Synthesis → Clarified Context
 → 用户检查 Clarified Context，手动点击「开始产品分析」
 → 产品分析（Product Analysis）
 → 用户检查分析结果，手动点击「开始收敛 MVP」
 → MVP 范围收敛（MVP Scoping，已实现）
 → 用户检查收敛结果，手动点击「生成执行方案」
 → 执行方案（Execution Planning，已实现）
 → 用户检查执行方案，手动点击「检查完整立项方案」
 → 最终一致性审查（Final Review，已实现，只读审计）
```

## 1. 首页（`/`）

**用户看见：**

- 顶部导航：左侧 `idea-launch` 产品标识；右侧「历史项目」「设置」入口
- Hero 主标题：**把一个想法，变成可以开始做的产品**
- 辅助说明文字
- 大型产品想法输入框（textarea）
- 产品想法模板（Product Idea Templates）：AI 应用 / SaaS / 开发者工具 / 效率工具，每个标签带一行一句话说明
- 主按钮：开始分析

**用户操作：**

- 在输入框中填写产品想法
- 可点击模板标签：点击后把该模板的示例 Prompt 填入输入框（仍可自由编辑）；再次点击或手动编辑导致内容偏离模板时自动取消选中态
- 模板只负责填入文案，不会自动开始分析
- 点击「开始分析」

**系统行为：**

- 校验输入非空（空输入时在页面内提示，不使用 alert）
- 检查当前激活 Provider 是否已配置 API Key：
  - 已配置 → 创建本地 Project，进入 Workspace 并发起 Idea Understanding
  - 未配置 → 打开设置弹窗，引导填写 API Key，保留已输入的想法内容
- 模板标签支持键盘操作（focus-visible 可见）与 aria-pressed 选中语义

## 2. 检查模型配置（设置弹窗，Settings V2）

设置弹窗自上而下四层：

1. **当前模型状态**：展示当前激活的 Provider 名称与模型 ID；未配置 Key 时明确提示
2. **Provider 选择**：紧凑 Radio 列表（无品牌 Logo）——火山方舟（豆包，默认）/ OpenAI / Anthropic / Google Gemini / 自定义（OpenAI 兼容，Qwen、DeepSeek、Kimi 等走此项）；切换 Provider 不清空其他 Provider 已保存的配置
3. **模型配置**：API Key（密码框，支持显示 / 隐藏）+ 模型 ID（可编辑输入框，附少量推荐模型 datalist）为主；Base URL 与 Protocol 收在「高级设置」折叠区，仅自定义 Provider 允许修改
4. **连接验证**：「测试连接」按钮及状态（测试中 / 成功 / 失败）

**用户操作：**

- 选择 Provider，粘贴对应 API Key，必要时调整模型 ID → 保存（写入 localStorage Settings V2）
- 点击测试连接验证可用性

**系统行为：**

- 发起真实端到端请求，依次验证：API 地址可达、API Key 有效、模型可用、支持结构化输出（要求模型返回 `{"ok":true}` 并做运行时校验）
- 成功：展示「Provider 名 · 模型 ID · 请求耗时」
- 失败：展示经过脱敏处理的用户可读错误（统一错误码中文文案）；任何情况下不展示 API Key、请求头或请求体
- 首次在新版本中打开设置时，若本地只有 V1 设置，自动惰性迁移为 V2（映射到火山方舟配置并设为激活），V1 原始数据保留不删

## 3. 首次理解（Workspace：`/project/[id]`，节点：产品想法）

**用户看见：**

- 顶部：项目名称、当前状态、设置入口
- 左侧流程导航：
  1. 产品想法（当前）
  2. 信息补全（理解完成后自动进入）
  3. 产品分析（信息补全完成后解锁）
  4. MVP（产品分析完成后解锁）
  5. 执行方案（MVP 收敛完成后解锁；Final Review 归属此阶段视图，导航不新增第六步）
- 右侧主工作区

**分析中状态（产品级状态，非思维链）：**

依次展示：

1. 正在理解你的产品想法
2. 正在识别目标用户
3. 正在提取核心问题
4. 正在检查已有约束
5. 正在识别缺失信息

配合 Skeleton / 轻量状态动画；不展示模型私有 Chain of Thought。

**分析完成：**

以结构化卡片展示：产品方向、一句话定义、目标用户、核心问题、主要场景、已知约束、当前假设、还需要确认的信息。

**系统行为：**

- 调用豆包 Seed 2.1 Pro，获取经 Schema 校验的结构化结果
- 成功后立即写入 localStorage，刷新页面可恢复
- 失败时在工作区内展示可理解错误，并允许重试

## 4. 历史项目

**用户操作：** 顶部「历史项目」打开项目列表。

**系统行为：**

- 读取本地已保存项目，按更新时间倒序展示
- 无项目时展示空状态，不创建假数据
- 点击项目进入对应 Workspace；支持删除项目与清空全部数据

## 5. 信息补全（Workspace 节点：Clarification，已实现）

### 5.1 问题生成（Question Generation，自动）

Idea Understanding 成功后自动进入信息补全，先发起一次模型调用。

**运行状态（产品级，非思维链）依次展示：**

1. 正在确认哪些信息会影响产品方向
2. 正在检查目标用户
3. 正在检查使用场景
4. 正在识别关键约束
5. 正在整理必要问题

**输出：** `clarificationNeeded`、`reason`、问题列表（正常 2 ～ 4 个，最多 5 个，允许空数组）。

### 5.2 逐题回答（Decision Card）

需要追问时，一次只展示一个核心问题：

- 顶部显示问题进度：`1 / 3`、进度条与「已回答 n 题」
- 问题大卡片：自然中文问题 + 一行弱化文字说明为什么需要确认（`whyItMatters`）
- 题型：单选题（选项卡片）、多选题（多选卡片）、文本题（textarea）
- 选择题选项为可点击卡片，不使用原生 radio 视觉；提供「自己填写」入口（当 `allowCustomAnswer` 为真）
- 单选题作答后轻微停留自动进入下一题；可随时「上一题」修改
- 每次回答立即写入 localStorage；切题、刷新都不会丢失已填答案
- 最后一题点击「完成信息补全」，提交前允许返回任意题目修改

### 5.3 无需澄清（0 题）

当模型判断信息已充分（`clarificationNeeded = false` 或问题为空）时，不进入空白问卷页，自动发起 Synthesis，完成后直接展示结果页，并提示「当前信息已经足够进入下一阶段，无需额外补充」。

### 5.4 上下文综合（Clarification Synthesis）

用户提交后再次调用模型，运行状态依次展示：

1. 正在整理你的产品上下文
2. 正在合并原始想法
3. 正在确认关键决策
4. 正在区分事实和假设
5. 正在准备产品分析上下文

### 5.5 结果页（Clarified Context）

完成后展示上下文摘要卡片：产品定义、一句话定义、核心用户、核心场景、核心问题、用户目标、替代方案、已确认决策、明确约束、仍然存在的假设（warning 标记）、暂时未知但不阻塞的信息（warning 标记）。

页面底部为可点击的 Indigo 主按钮「开始产品分析」。**产品分析只能由用户主动启动**，Clarification 完成后不自动调用，方便用户先检查已补全的上下文；点击后按钮进入「正在开始」禁用态，防止重复提交。

### 5.6 失败与恢复

- 问题生成 / Synthesis 失败：工作区内展示脱敏错误卡片与「重试」按钮，禁止 `alert()`
- 已填写答案即使请求失败也保留在本地，重试不需要重答
- 刷新恢复规则：
  - 只完成理解 → 自动继续生成问题
  - 问题已生成但未答完 → 恢复到第一个未回答的问题，已填答案保留
  - 已答完但 Synthesis 未完成 / 失败 → 停留在问题页，可重新提交（刷新不自动重发失败请求）
  - 已完成 → 直接展示 Clarified Context；刷新不重新生成问题、不重复调用 Synthesis

## 6. 产品分析（Workspace 节点：Product Analysis，已实现）

### 6.1 启动

Clarified Context 页面底部「开始产品分析」为唯一入口，必须由用户手动点击。系统不自动发起调用，因此：

- Clarification 刚完成时停留在结果页，等待用户检查
- 直播演示时可明确展示「信息已经补全 → 现在开始产品分析」的节奏

### 6.2 分析中（产品级状态，非思维链）

左侧导航：产品想法 ✓、信息补全 ✓、产品分析 ●（当前）、MVP ○、执行方案 ○。

主区域标题下展示「正在分析这个产品是否解决了一个足够明确的问题」，步骤文案轮换：

1. 正在收敛核心用户
2. 正在分析核心使用场景
3. 正在识别用户当前替代方式
4. 正在梳理产品核心价值
5. 正在检查关键假设
6. 正在识别主要风险

不展示模型 Chain of Thought。

### 6.3 结果页（结构化卡片，非 Markdown）

- 顶部成功横幅「产品分析完成」
- 第一屏两张大卡：**产品判断摘要**（产品名称、分类 / 阶段标签、一句话定义、核心用户、核心场景）与**用户真正遇到的问题**（核心问题 + 问题根因 + 当前摩擦）
- 向下依次：用户现在怎么解决（替代方式小卡片，非竞品矩阵）、产品价值（淡紫 / 淡蓝强调卡）、关键假设（假设内容 + 高 / 中 / 低优先级 + 验证建议）、主要风险（克制的 Risk Cards，高风险使用少量暖橙色）
- 底部「下一阶段应该关注什么」：列出 MVP 收敛关注点；`readyForMvpScoping = true` 时展示可点击的 Indigo 主按钮「开始收敛 MVP」，点击后按钮进入「正在开始」禁用态，防止重复提交
- 右下角以 mono xs 展示真实分析耗时（durationMs）

### 6.4 失败与恢复

- 失败：保留 Idea Understanding 与 Clarification（含已填答案、Clarified Context）全部数据，展示脱敏错误卡片与「重试」，禁止 `alert()`
- 刷新恢复规则：
  - Clarification 已完成、Product Analysis 未开始 → 展示 Clarified Context，可点击开始
  - 请求进行中刷新 → 请求丢失时安全退回到 Clarified Context，允许重新开始，不假装成功
  - 已完成 → 直接展示分析结果，**绝不重新调用模型**（无自动 effect），避免重复计费

## 7. MVP 范围收敛（Workspace 节点：MVP Scoping，已实现）

### 7.1 启动

Product Analysis 结果页底部「开始收敛 MVP」为唯一入口，必须由用户手动点击，系统不自动发起调用。直播演示时可明确展示「产品分析已经完成 → 现在决定第一版到底做什么」的转折。

### 7.2 收敛中（产品级状态，非思维链）

左侧导航：产品想法 ✓、信息补全 ✓、产品分析 ✓、MVP ●（当前）、执行方案 ○。

主区域展示产品级步骤文案轮换：

1. 正在确定第一版最重要的验证目标
2. 正在寻找最小完整用户闭环
3. 正在判断哪些能力必须保留
4. 正在主动删除暂时不需要的功能
5. 正在检查独立开发约束
6. 正在准备验证方案

不展示模型 Chain of Thought。

### 7.3 结果页（结构化卡片，非 Markdown）

- 顶部成功横幅「MVP 范围已经收敛」
- 第一屏依次为 **MVP 定义**（目标 / 第一优先用户 / 核心场景 / 核心价值）与 **这一版首先验证什么**（唯一 primaryHypothesis + 为什么优先 + 怎么判断）
- 核心视觉对比 **第一版必须做**（Indigo 浅底，3～6 张功能卡：功能 / 用户需要 / 为什么必须 / 完成标准）与 **现在先不做 · 以后再考虑**（淡紫：暂缓能力 + 重新考虑条件）、**当前方向明确不做**（弱灰）；「不做」类内容不使用红色
- 向下依次：最小完整用户闭环（3～6 个节点的箭头流程图，起点 Indigo、终点 success）、范围约束、MVP 风险与上线后怎么验证（双栏）、范围总结（现在做 / 现在不做）
- 底部为可点击的 Indigo 主按钮「生成执行方案」，辅助文案说明「将把已冻结的 MVP 范围展开为可以开始开发的安排，不会新增功能」；点击后按钮替换为 spinner +「正在生成…」并禁用，防止重复提交
- 右下角以 mono xs 展示真实收敛耗时（durationMs）

### 7.4 失败与恢复

- 失败：保留 Idea Understanding、Clarification、Product Analysis 全部数据，展示脱敏错误卡片与「重试」，禁止 `alert()`
- 刷新恢复规则：
  - Product Analysis 已完成、MVP 未开始 → 展示产品分析结果，可点击「开始收敛 MVP」
  - MVP 请求失败 → 保留前三阶段数据与错误态，允许重新收敛
  - MVP 已完成 → 直接展示收敛结果，**绝不重新调用模型**（无自动 effect），刷新零模型请求

## 8. 执行方案（Workspace 节点：Execution Planning，已实现）

### 8.1 启动

MVP Scoping 结果页底部「生成执行方案」为唯一入口，必须由用户手动点击，系统不自动发起调用。直播演示时可明确展示「MVP 范围已经冻结 → 现在把它变成可以开始开发的安排」的转折。

### 8.2 生成中（产品级状态，非思维链）

左侧导航（固定五项）：产品想法 ✓、信息补全 ✓、产品分析 ✓、MVP ✓、执行方案 ●（当前；Final Review 运行态在主区域展示，不新增导航项）。

主区域标题下展示主文案「正在把 MVP 转化成可以开始开发的计划」，步骤文案轮换：

1. 正在整理产品结构
2. 正在选择最简单的技术路径
3. 正在拆解核心数据对象
4. 正在组织开发里程碑
5. 正在拆分可执行任务
6. 正在检查任务依赖与验收标准

不展示模型 Chain of Thought。

### 8.3 结果页（结构化 Workspace，非 Markdown）

- 顶部成功横幅「执行方案已经生成」
- **第一屏**优先展示执行目标（goal / deliveryTarget / 第一优先用户 / 核心场景）、**现在先做什么**（firstActions 有序列表，accent 浅底卡）与**开发阶段**（milestones 垂直时间线：序号圆圈与连接线，只表达阶段、目标、交付物与验收标准；不伪造日期、不做甘特图）
- 开发任务：显示任务总数，按里程碑分组折叠（Accordion，默认展开第一组）；任务卡含任务 ID、标题、类型与工作量标签、目标、依赖（解析为「T0x 任务标题」）与可人工验收的验收项
- 向下依次：产品结构（userFlow 胶囊箭头流 + surfaces 界面卡）、轻量技术路径（总体架构 + 前端 / 后端 / AI / 存储 / 外部服务分层卡；MVP 不需要 AI 时显示「本阶段不需要」）、核心数据对象卡、验证节点卡、执行风险卡（高风险仅用少量暖橙）
- 页面下方明显视觉区域「第一版做到这里就可以停」（success 浅底，definitionOfDone 对勾列表）；底部为可点击的 Indigo 主按钮「检查完整立项方案」，辅助文案说明这是只读一致性检查、不会改动方案
- 右下角以 mono xs 展示真实生成耗时（durationMs）

### 8.4 失败与恢复

- 失败：保留 Idea Understanding、Clarification、Product Analysis、MVP Scoping 全部数据，展示脱敏错误卡片与「重试」，禁止 `alert()`
- 刷新恢复规则：
  - MVP 已完成、执行方案未开始 → 展示 MVP 收敛结果，可点击「生成执行方案」
  - 执行方案请求失败 → 保留前四阶段数据与错误态，允许重新生成
  - 执行方案已完成 → 直接展示结构化结果，**绝不重新调用模型**（无自动 effect），刷新零模型请求

## 9. 最终一致性审查（Final Review，已实现）

### 9.1 启动

Execution Planning 结果页底部「检查完整立项方案」为唯一入口，必须由用户手动点击，系统不自动发起调用。

### 9.2 审查中（产品级状态，非思维链）

主区域展示审查步骤轮换：核对原始想法与方案是否一致、检查已排除能力是否回流、核对事实与假设边界、评估执行准备度、整理最终结论。不展示模型 Chain of Thought。

### 9.3 结果页（只读审计）

- 顶部结论区：verdict（ready「可以开始开发」/ needs_attention「方案还需要调整」，无分数）+ 5～7 项一致性检查 + 第一件事
- 三段审计卡：范围完整性（reintroducedItems / finding）、事实完整性（issues / finding）、执行准备度（strengths / gaps）
- 调整建议：0～5 条，按 high / medium / low 与对应阶段（clarification / product_analysis / mvp / execution）分组；只给建议，不自动修改任何上游数据
- 底部「方案已经准备好」与 keepInMind（2～4 条），可返回历史项目或重新查看执行方案
- 右下角以 mono xs 展示真实审查耗时（durationMs）

### 9.4 失败与恢复

- 失败：保留全部前序结果（含 Execution Planning），展示脱敏错误卡片与「重试」，禁止 `alert()`
- 刷新恢复规则：
  - Execution Planning 已完成、Final Review 未开始 → 展示执行方案与可点击入口
  - Final Review 请求失败 → 保留前序结果与错误态，允许重试；刷新不自动重试
  - Final Review 已完成 → 直接展示审计结果，**绝不重新调用模型**，刷新零模型请求
