# 02 · 用户流程（User Flow）

> 描述 idea-launch 完整用户流程。当前实现「首页 → 输入想法 → 检查配置 → 首次理解 → 信息补全 → 产品分析 → MVP 范围收敛」，执行方案及之后仅定义规格。

## 总览

```
首页
 → 输入产品想法
 → 检查模型配置
 → 首次理解（Idea Understanding）
 → 判断信息是否充分（Clarification Question Generation）
 → ├─ 需要补充：逐题回答（Clarification）
 │  └─ Clarification Synthesis → Clarified Context
 └─ 无需补充（0 题）：自动 Clarification Synthesis → Clarified Context
 → 用户检查 Clarified Context，手动点击「开始产品分析」
 → 产品分析（Product Analysis）
 → 用户检查分析结果，手动点击「开始收敛 MVP」
 → MVP 范围收敛（MVP Scoping，已实现）
 → 执行方案（Execution Planning）    ← 后续阶段（当前版本暂未开放）
 → 最终报告（Final Review）          ← 后续阶段
```

## 1. 首页（`/`）

**用户看见：**

- 顶部导航：左侧 `idea-launch` 产品标识；右侧「历史项目」「设置」入口
- Hero 主标题：**把一个想法，变成可以开始做的产品**
- 辅助说明文字
- 大型产品想法输入框（textarea）
- 轻量场景标签：AI 应用 / SaaS / 开发者工具 / 效率工具
- 主按钮：开始分析

**用户操作：**

- 在输入框中填写产品想法
- 可点击场景标签（仅作为轻量辅助，不强制）
- 点击「开始分析」

**系统行为：**

- 校验输入非空（空输入时在页面内提示，不使用 alert）
- 检查是否已配置 API Key：
  - 已配置 → 创建本地 Project，进入 Workspace 并发起 Idea Understanding
  - 未配置 → 打开设置弹窗，引导填写 API Key，保留已输入的想法内容

## 2. 检查模型配置（设置弹窗）

**用户看见：**

- API Key 密码输入框（支持显示 / 隐藏）
- 模型：豆包 Seed 2.1 Pro（`doubao-seed-2.1-pro`）
- API 地址（默认 `https://ark.cn-beijing.volces.com/api/plan/v3`，可编辑，可恢复默认）
- 「测试连接」按钮及状态（测试中 / 成功 / 失败）

**用户操作：**

- 粘贴 API Key → 保存（写入 localStorage）
- 点击测试连接验证可用性

**系统行为：**

- 发起真实 Responses API 请求
- 成功：展示「已连接 / 模型名 / 请求耗时」
- 失败：展示经过脱敏处理的用户可读错误；任何情况下不展示 API Key

## 3. 首次理解（Workspace：`/project/[id]`，节点：产品想法）

**用户看见：**

- 顶部：项目名称、当前状态、设置入口
- 左侧流程导航：
  1. 产品想法（当前）
  2. 信息补全（理解完成后自动进入）
  3. 产品分析（信息补全完成后解锁）
  4. MVP（产品分析完成后解锁）
  5. 执行方案（暂未开放）
- 右侧主工作区

**分析中状态（产品级状态，非思维链）：**

依次展示：

1. 正在理解你的产品想法
2. 正在识别目标用户
3. 正在提取核心问题
4. 正在检查已有约束
5. 正在识别缺失信息

配合 Skeleton / 轻量状态动画；不展示模型私有 Chain of Thought。

**分析完成：**

以结构化卡片展示：产品方向、一句话定义、目标用户、核心问题、主要场景、已知约束、当前假设、还需要确认的信息。

**系统行为：**

- 调用豆包 Seed 2.1 Pro，获取经 Schema 校验的结构化结果
- 成功后立即写入 localStorage，刷新页面可恢复
- 失败时在工作区内展示可理解错误，并允许重试

## 4. 历史项目

**用户操作：** 顶部「历史项目」打开项目列表。

**系统行为：**

- 读取本地已保存项目，按更新时间倒序展示
- 无项目时展示空状态，不创建假数据
- 点击项目进入对应 Workspace；支持删除项目与清空全部数据

## 5. 信息补全（Workspace 节点：Clarification，已实现）

### 5.1 问题生成（Question Generation，自动）

Idea Understanding 成功后自动进入信息补全，先发起一次模型调用。

**运行状态（产品级，非思维链）依次展示：**

1. 正在确认哪些信息会影响产品方向
2. 正在检查目标用户
3. 正在检查使用场景
4. 正在识别关键约束
5. 正在整理必要问题

**输出：** `clarificationNeeded`、`reason`、问题列表（正常 2 ～ 4 个，最多 5 个，允许空数组）。

### 5.2 逐题回答（Decision Card）

需要追问时，一次只展示一个核心问题：

- 顶部显示问题进度：`1 / 3`、进度条与「已回答 n 题」
- 问题大卡片：自然中文问题 + 一行弱化文字说明为什么需要确认（`whyItMatters`）
- 题型：单选题（选项卡片）、多选题（多选卡片）、文本题（textarea）
- 选择题选项为可点击卡片，不使用原生 radio 视觉；提供「自己填写」入口（当 `allowCustomAnswer` 为真）
- 单选题作答后轻微停留自动进入下一题；可随时「上一题」修改
- 每次回答立即写入 localStorage；切题、刷新都不会丢失已填答案
- 最后一题点击「完成信息补全」，提交前允许返回任意题目修改

### 5.3 无需澄清（0 题）

当模型判断信息已充分（`clarificationNeeded = false` 或问题为空）时，不进入空白问卷页，自动发起 Synthesis，完成后直接展示结果页，并提示「当前信息已经足够进入下一阶段，无需额外补充」。

### 5.4 上下文综合（Clarification Synthesis）

用户提交后再次调用模型，运行状态依次展示：

1. 正在整理你的产品上下文
2. 正在合并原始想法
3. 正在确认关键决策
4. 正在区分事实和假设
5. 正在准备产品分析上下文

### 5.5 结果页（Clarified Context）

完成后展示上下文摘要卡片：产品定义、一句话定义、核心用户、核心场景、核心问题、用户目标、替代方案、已确认决策、明确约束、仍然存在的假设（warning 标记）、暂时未知但不阻塞的信息（warning 标记）。

页面底部为可点击的 Indigo 主按钮「开始产品分析」。**产品分析只能由用户主动启动**，Clarification 完成后不自动调用，方便用户先检查已补全的上下文；点击后按钮进入「正在开始」禁用态，防止重复提交。

### 5.6 失败与恢复

- 问题生成 / Synthesis 失败：工作区内展示脱敏错误卡片与「重试」按钮，禁止 `alert()`
- 已填写答案即使请求失败也保留在本地，重试不需要重答
- 刷新恢复规则：
  - 只完成理解 → 自动继续生成问题
  - 问题已生成但未答完 → 恢复到第一个未回答的问题，已填答案保留
  - 已答完但 Synthesis 未完成 / 失败 → 停留在问题页，可重新提交（刷新不自动重发失败请求）
  - 已完成 → 直接展示 Clarified Context；刷新不重新生成问题、不重复调用 Synthesis

## 6. 产品分析（Workspace 节点：Product Analysis，已实现）

### 6.1 启动

Clarified Context 页面底部「开始产品分析」为唯一入口，必须由用户手动点击。系统不自动发起调用，因此：

- Clarification 刚完成时停留在结果页，等待用户检查
- 直播演示时可明确展示「信息已经补全 → 现在开始产品分析」的节奏

### 6.2 分析中（产品级状态，非思维链）

左侧导航：产品想法 ✓、信息补全 ✓、产品分析 ●（当前）、MVP ○、执行方案 ○。

主区域标题下展示「正在分析这个产品是否解决了一个足够明确的问题」，步骤文案轮换：

1. 正在收敛核心用户
2. 正在分析核心使用场景
3. 正在识别用户当前替代方式
4. 正在梳理产品核心价值
5. 正在检查关键假设
6. 正在识别主要风险

不展示模型 Chain of Thought。

### 6.3 结果页（结构化卡片，非 Markdown）

- 顶部成功横幅「产品分析完成」
- 第一屏两张大卡：**产品判断摘要**（产品名称、分类 / 阶段标签、一句话定义、核心用户、核心场景）与**用户真正遇到的问题**（核心问题 + 问题根因 + 当前摩擦）
- 向下依次：用户现在怎么解决（替代方式小卡片，非竞品矩阵）、产品价值（淡紫 / 淡蓝强调卡）、关键假设（假设内容 + 高 / 中 / 低优先级 + 验证建议）、主要风险（克制的 Risk Cards，高风险使用少量暖橙色）
- 底部「下一阶段应该关注什么」：列出 MVP 收敛关注点；`readyForMvpScoping = true` 时展示可点击的 Indigo 主按钮「开始收敛 MVP」，点击后按钮进入「正在开始」禁用态，防止重复提交
- 右下角以 mono xs 展示真实分析耗时（durationMs）

### 6.4 失败与恢复

- 失败：保留 Idea Understanding 与 Clarification（含已填答案、Clarified Context）全部数据，展示脱敏错误卡片与「重试」，禁止 `alert()`
- 刷新恢复规则：
  - Clarification 已完成、Product Analysis 未开始 → 展示 Clarified Context，可点击开始
  - 请求进行中刷新 → 请求丢失时安全退回到 Clarified Context，允许重新开始，不假装成功
  - 已完成 → 直接展示分析结果，**绝不重新调用模型**（无自动 effect），避免重复计费

## 7. MVP 范围收敛（Workspace 节点：MVP Scoping，已实现）

### 7.1 启动

Product Analysis 结果页底部「开始收敛 MVP」为唯一入口，必须由用户手动点击，系统不自动发起调用。直播演示时可明确展示「产品分析已经完成 → 现在决定第一版到底做什么」的转折。

### 7.2 收敛中（产品级状态，非思维链）

左侧导航：产品想法 ✓、信息补全 ✓、产品分析 ✓、MVP ●（当前）、执行方案 ○。

主区域展示产品级步骤文案轮换：

1. 正在确定第一版最重要的验证目标
2. 正在寻找最小完整用户闭环
3. 正在判断哪些能力必须保留
4. 正在主动删除暂时不需要的功能
5. 正在检查独立开发约束
6. 正在准备验证方案

不展示模型 Chain of Thought。

### 7.3 结果页（结构化卡片，非 Markdown）

- 顶部成功横幅「MVP 范围已经收敛」
- 第一屏依次为 **MVP 定义**（目标 / 第一优先用户 / 核心场景 / 核心价值）与 **这一版首先验证什么**（唯一 primaryHypothesis + 为什么优先 + 怎么判断）
- 核心视觉对比 **第一版必须做**（Indigo 浅底，3～6 张功能卡：功能 / 用户需要 / 为什么必须 / 完成标准）与 **现在先不做 · 以后再考虑**（淡紫：暂缓能力 + 重新考虑条件）、**当前方向明确不做**（弱灰）；「不做」类内容不使用红色
- 向下依次：最小完整用户闭环（3～6 个节点的箭头流程图，起点 Indigo、终点 success）、范围约束、MVP 风险与上线后怎么验证（双栏）、范围总结（现在做 / 现在不做）
- 底部「生成执行方案」按钮保持 disabled（Lock 图标 + 「下一阶段开放」）
- 右下角以 mono xs 展示真实收敛耗时（durationMs）

### 7.4 失败与恢复

- 失败：保留 Idea Understanding、Clarification、Product Analysis 全部数据，展示脱敏错误卡片与「重试」，禁止 `alert()`
- 刷新恢复规则：
  - Product Analysis 已完成、MVP 未开始 → 展示产品分析结果，可点击「开始收敛 MVP」
  - MVP 请求失败 → 保留前三阶段数据与错误态，允许重新收敛
  - MVP 已完成 → 直接展示收敛结果，**绝不重新调用模型**（无自动 effect），刷新零模型请求

## 8. 后续阶段流程（仅规格）

### 8.1 执行方案 Execution Planning

技术路径建议 + 开发任务拆解。输出：技术栈建议、里程碑、任务列表。

### 8.2 最终报告 Final Review

汇总全部工件，生成立项方案；支持本地查看与 Markdown 导出。

> 每一阶段都有独立的入口与出口，用户可在左侧导航中回看历史阶段产物。
